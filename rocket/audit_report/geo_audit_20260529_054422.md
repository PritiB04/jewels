## 1. AI Crawler Access — Missing Explicit Allow Rules — [Status: Needs Improvement]

**GEO Impact:** High
**Affected Files:** `src/app/robots.ts` (line 1–16)

The robots.ts file does not explicitly allow AI crawlers (GPTBot, anthropic-ai, PerplexityBot, Google-Extended) to access public routes. This prevents AI-powered search engines and answer engines from indexing and retrieving product information, reducing visibility in GEO/AEO results.

**Current Implementation:** Generic `userAgent: '*'` rule without specific AI crawler allowlists.

**Evidence:** `src/app/robots.ts` (line 6–11) — The rules array only contains a generic wildcard rule without dedicated AI crawler entries.

**Impact:** AI search engines cannot reliably crawl product pages, FAQs, and comparison content, limiting discoverability in generative search results.

## 2. Schema Injection Timing — Client-Side Only — [Status: Needs Improvement]

**GEO Impact:** High
**Affected Files:** `src/components/SchemaInjector.tsx` (line 1–74), `src/app/page.tsx` (line 1–74)

Schema markup is injected client-side via useEffect in SchemaInjector.tsx. This delays schema availability to crawlers and may cause issues with server-side rendering. Best practice requires schema to be present in the initial HTML response for optimal GEO/AEO crawling.

**Current Implementation:** `'use client'` component with useEffect-based script injection (line 15–60).

**Evidence:** `src/components/SchemaInjector.tsx` (line 15–60) — All schema scripts are created and appended to document.head inside useEffect, which runs after hydration.

**Impact:** Crawlers may miss schema markup on first pass, reducing structured data indexing quality for AI search engines.

## 4. WebPage Schema — Missing dateModified Best Practice — [Status: Needs Improvement]

**GEO Impact:** Medium
**Affected Files:** `src/app/page.tsx` (line 47–48)

The WebPage schema uses `new Date().toISOString().split('T')[0]` which generates a dynamic date on every page load. Best practice requires a fixed build-time date to ensure consistency and prevent unnecessary schema updates.

**Current Implementation:** `dateModified: new Date().toISOString().split('T')[0]` (line 47).

**Evidence:** `src/app/page.tsx` (line 47) — Dynamic date generation instead of fixed build-time value.

**Impact:** Schema changes on every request, potentially confusing crawlers about actual content modification dates.
